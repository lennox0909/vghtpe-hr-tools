# **輕量級的混合式模糊檢索 (Hybrid Fuzzy Search) 系統**

- 不依賴龐大的向量資料庫，而是透過「字串前處理」與「多維度加權評分 (Scoring System)」來找出最符合使用者問題的 FAQ 資料。

各項演算法詳細說明：

## 1. 文本正規化與前處理 (Text Normalization)
在進行任何比對之前，系統會先對使用者的輸入 (`userMessage`) 以及資料庫中的題目 (`item.q`) 進行「清洗」，降低因為標點符號或全半角差異導致的誤判。
* **演算法實作**：使用正規表達式 (Regular Expression) `/[?？!！,，.。~～\s]/g` 過濾掉常見的問號、驚嘆號、逗號、句號與空白字元，並全面轉換為小寫 (`toLowerCase()`)。
* **目的**：讓「請假規定？」與「請假規定」在後續比對時能被視為完全相同的字串。

## 2. 加權評分演算法 (Scoring & Weighting Algorithm)
系統會走訪知識庫 (`faqDatabase`) 中的每一筆資料，並進行四個階段的檢索與給分。分數越高，代表該筆資料與使用者問題的關聯性越強：

### A. 精準命中判定 (Exact Match)
* **邏輯**：判斷清洗後的使用者問題，是否與清洗後的 FAQ 題目「完全一致」。或者未清洗的原始輸入完全等同於原始題目。
* **權重**：`+1000` 分。
* **目的**：這是一個「覆寫 (Override)」機制。通常發生在使用者直接點擊了 UI 上的「建議問題按鈕」，此時不需要進行模糊搜尋，直接給予壓倒性的極高分，確保它一定排在第一名。

### B. 關鍵字比對 (Keyword Matching)
* **邏輯**：針對資料庫中預先定義的 `keywords` 陣列進行交叉比對。
* **權重**：
  * 使用者輸入「包含」預設關鍵字 (`query.includes(kw)`)：`+20` 分。
  * 預設關鍵字「包含」使用者輸入 (`kw.includes(query)`)：`+10` 分。
* **目的**：透過人工定義的標籤來提高精準度。例如關鍵字有「特休」，當使用者問「我有幾天特休」時就能觸發高分。

### C. 全文包含比對 (Full-text Substring Matching)
* **邏輯**：檢查使用者的問題是否作為「子字串 (Substring)」出現在 FAQ 的各個欄位中，或是各個欄位是否包含在使用者問題中。
* **權重**：
  * 命中「法規依據」 (`regulation`)：`+20` 分 (法規專有名詞權重最高)。
  * 命中「問題」 (`q`)：`+15` 分。
  * 命中「答案」 (`a`) 或「類別」 (`type`)：`+10` 分。
* **目的**：擴大檢索範圍，即使沒有精準命中，只要問題或答案中含有相關字眼，就能獲得基礎分數。

### D. 雙連字 (Bigram) 模糊比對 / 容錯機制
* **邏輯**：這是一種基於 **N-gram 語言模型** 的概念。演算法會將使用者的問題切成「每兩個字一組」的滑動窗口（例如：「生理假」會被切成 `[生理, 理假]`），然後拿這些雙字詞去比對各欄位。
* **權重**：
  * 命中「問題」 (`q`)：`+5` 分。
  * 命中「答案」 (`a`)：`+3` 分。
  * 命中「法規」或「類別」：`+2` 分。
  * *(若使用者只輸入單一個字，則降級為 Unigram 單字比對，給予 1~3 分不等的微小加分)*。
* **目的**：**提供容錯能力**。假設使用者打錯字或使用了稍微不同的斷詞（例如資料庫是「請生理假」，使用者打「生理休假」），雖然全文比對會失敗，但透過 Bigram 拆解，依然能撈出部分相同的字詞組合，累積一定分數。

## 3. 排序與篩選演算法 (Ranking & Filtering)
當所有資料都計算出 `score` 之後，系統會進行最後的過濾與排序：
1. **門檻過濾 (Thresholding)**：`filter(item => item.score > 0)`，直接剔除完全沒有相關性（零分）的資料，避免塞入無用資訊。
2. **降冪排序 (Descending Sort)**：`sort((a, b) => b.score - a.score)`，根據剛才計算出來的總分，由高到低排序。
3. **Top-K 截斷 (Truncation)**：`slice(0, topK)`，預設只取前 3 名最高分的資料。

## 4. 上下文組合 (Context Assembly)
最後，演算法會根據排序結果，將這些 FAQ 資料重新組合成一段特定的字串格式 (`context`)：
* 如果有觸發「精準命中 (`isExactMatch`)」，第一筆資料會被標示為 `[精準命中資料]` 並附上完整問答、法規與類別。
* 其他名次的資料則作為輔助參考 (`[資料 2]`, `[資料 3]`)，同時提取出它們的 `q` 放入 `questions` 陣列，準備提供給 LLM 或前端作為後續的「延伸推薦問題」。
